S4
==

S4 was introduced (apparently by Bioconductor) and can be thought of
as a more strict, more featureful version of S3 (much closer in spirt
to The Common Lisp Object System, in fact).

Alas, S4 is kind of a cursed object system because once you learn it
you will understood the power of multiple dispatch object systems and
this powerful, fun, feature is not present in the vast majority of
systems you will encounter outside of R.

In S4 class definitions consist of a class name, slots, and a`contains`.

This formalizes the notions of structures and inheritence. Slots are a
little weird.

With our basic classes and hierarchies in place we can create instances:

``` R session=eg_s4 capture
fido  <- new("Dog",  name = "Fido")
milo  <- new("Cat",  name = "Milo")
todd  <- new("Fox",  name = "Todd")
shep  <- new("BorderCollie", name = "Shep")
bob   <- new("Person", name = "Bob")
ada   <- new("Person", name = "Ada")

make_sound(fido) 
make_sound(shep)
make_sound(todd)
make_sound(bob)
```
S4 has a nice trick up its sleeve, however: multiple dispath - this allows us 
to specify a different behavior for a method based on the types of multiple parameters:

``` R file=eg_s4.R start=28 end=50 session=eg_s4

```
Such that:

``` R session=eg_s4 capture
fido  <- new("Dog",  name = "Fido")
milo  <- new("Cat",  name = "Milo")
todd  <- new("Fox",  name = "Todd")
shep  <- new("BorderCollie", name = "Shep")
bob   <- new("Person", name = "Bob")
ada   <- new("Person", name = "Ada")

make_sound(fido)   # "Woof!"
make_sound(shep)   # "Ruff!"
make_sound(todd)   # "Yip!"
make_sound(bob)    # "Bob"

interact(bob, fido)  # "Bob plays fetch with Fido"
interact(fido, milo) # "Fido chases Milo"
interact(milo, fido) # "Milo hisses at Fido"
interact(fido, todd) # "Fido barks at Todd"
interact(todd, fido) # "Todd dodges Fido"
interact(bob, ada)   # "Bob says hello to Ada"
interact(bob, milo)  # "Bob and Milo acknowledge each other"
```
This is pretty much how the Common Lisp Object System works.

https://en.wikipedia.org/wiki/Common_Lisp_Object_System

There are some decided downsides to this kind of system:

1. it is extremely unusual in the world of object oriented programming
2. method definitions don't have a natural home - do we define `interact<dog><human>`  nex to the code for dog or the code for human?

On the other hand we have implicitly solved many issues with single dispatch object systems where interactions
typically need to be lifted into their own special class.

Furthermore, these objects systems treat methods as just any other type of function
and so we can use them in functional-style programs:

``` R session=eg_s4 capture
Map(make_sound, list(fido, milo, todd, bob))
```

"Luckily" R has a more conventional object system as well: ::04_r5:R5::.
